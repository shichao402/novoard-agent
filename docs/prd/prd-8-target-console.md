# PRD-8 Target 控制台与运行视图

依据 [ADR-0021](../adr/0021-run-history-from-trace.md)。取代 PRD-1 中「快捷操作页」的界面形态与 PRD-2 中「Target 页即编辑器」的入口设计；执行语义、状态枚举不变。

## 背景

改版前控制台把三件事摊在一页：

- 快捷操作页是卡片墙，点 ▶ 触发。
- 同一页底部钉着一个输出面板，一次只能看一个 target，历次运行只能从下拉框按 taskId 选，没有成败、触发来源、耗时，也看不出停在哪一步。
- Target 页一进来就是编辑表单，没有只读的观察视图。

结果是：想知道「这个 target 最近怎么样」要在两页之间来回切；「并发已满」只是一行红字，看不到是谁占着；Hub 或定时触发的运行在界面上几乎不可见。

## 目标

按「对象列表 → 对象详情 → 单次运行详情」组织控制台，参照 Rundeck 的 Job、GitHub Actions 的 workflow / run、Vercel 的 Project / Deployment：

- 列表能搜、能筛、能直接运行，不点开就看得到最近一次结果。
- 详情页是观察视图：定义、定时、在跑的那一次、历次运行；编辑是详情下的二级页面。
- 每次运行有自己的页面，按步骤展示状态、耗时与日志。
- 全局「运行」页集中显示运行中、排队、等待审批和最近完成的运行，能取消。

非目标：Hub 网页端改版、运行时传参以外的触发方式、跨机器的运行聚合。

## 信息架构

侧边栏：概览、对话、Target、运行、能力包、日志、设置。「快捷操作」入口删除，它的职责并入 Target 列表。

| 路由 | 页面 |
| --- | --- |
| `#/targets` | Target 列表 |
| `#/targets/new` | 新建 Target（编辑表单） |
| `#/targets/:id` | Target 详情，默认「概览」 |
| `#/targets/:id/runs` | Target 详情的「运行记录」 |
| `#/targets/:id/edit` | 编辑 Target |
| `#/runs` | 全局运行页 |
| `#/runs/:taskId` | 运行详情 |

`#/actions` 重定向到 `#/targets`；托盘菜单「快捷操作」改为「运行」。

界面不放解释性文字，路径、保留天数等信息收进按钮或提示。

## 页面规格

### T1 Target 列表

- 一行一个 target：状态点、标题、id、最近一次结果（状态、相对时间、耗时、触发来源）或当前进度（第 i/n 步、已运行时长）、定时与下次运行时间、▶ 运行按钮。运行中的行显示 ■ 取消按钮。
- 搜索框匹配 id 与标题；筛选：全部、运行中、失败、定时、有问题。「失败」指最近一次终态为 failed 或中断。
- 有诊断问题的行标红，展开显示问题与「去能力包页」。
- 带定时的 target 存在时，顶部显示定时总开关、时区与「立即补跑」。
- 右上「新建」进 `#/targets/new`。
- 点行进入详情；▶ 沿用原有流程：带输入的先弹输入框，需审批的先确认。

### T2 Target 详情

页头：返回、标题、id、暴露范围、超时、并发；右侧「运行」「编辑」。

概览 Tab：

- 在途运行卡：当前每一步的状态与耗时，正在跑的那步显示进度文字；按钮「查看」「取消」。同一 target 多个在途时逐个列出。
- 最近 20 次的状态条，每格一个运行，点击进运行详情。
- 步骤定义（只读）、定时（表达式、下次、上次定时结果）、运行方式（审批、通知、离线、审计）。

运行记录 Tab：表格列出状态、开始时间、触发来源、耗时、结果（失败时为「第 N 步 exit X」），点行进运行详情。

### T3 编辑 Target

现有表单原样保留，按单个 target 编辑。保存仍然整表 PUT `/api/targets`，只替换当前这一项。新建保存后跳到新 target 的详情；删除确认后立即保存并回到列表。改 id 后跳到新 id 的详情。

### R1 运行详情

- 面包屑：target 标题 / taskId。
- 摘要：状态、耗时（在途时实时走）、触发来源、开始时间；按钮「再次运行」「取消」（在途时）「原始日志」（显示日志相对路径并可复制）。
- 步骤时间线：每步一行，状态图标、序号、命令、耗时；点开看这一步的日志。失败的步骤默认展开；在途时当前步默认展开并跟随滚动。进度类日志（「进度 第 i 步：…」）显示为该步的进度文字，不混在输出里。
- 不属于任何步骤的行（开始、排队、结束）放在时间线首尾。

### R2 全局运行页

- 三段：运行中、排队与等待审批、最近完成（最近 50 次）。
- 运行中与排队可取消；等待审批的只展示，审批在 Hub 上做。
- 侧边栏「运行」显示在途数量角标。

## 接口（本机，非契约）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/runs?target=&limit=` | `{ live, runs }`：在途快照与历史摘要，历史按开始时间倒序 |
| `GET` | `/api/runs/:taskId` | 单次运行摘要、在途进度与按步归属的日志行 |
| `POST` | `/api/runs/:taskId/cancel` | 取消运行中或排队中的任务，同源校验，写审计 |

摘要字段：`taskId`、`target`、`title`、`trigger`、`startedAt`、`endedAt`、`state`、`steps[{ index, command, startedAt, endedAt, exit }]`、`failedStep`、`log`。在途字段：`state`（working、queued、input-required）、`step`、`total`、`message`、`blockedBy`。

`/api/shortcuts/:id/runs*` 保留兼容，控制台不再使用。

## 验收

- 截图场景：定时 target `gamecoreonly-daily-svn-update` 跑完后，列表行显示「完成 · 17s · 定时」；详情状态条最右一格为绿色；运行详情三步各自显示耗时，第 3 步展开能看到 svn 输出，进度行显示为步骤进度文字。
- Hub 委派的运行与本机触发的运行在运行页同时可见。
- 重启 agent 后，列表的最近一次结果与运行记录仍在。
- 运行中重启 agent，重启后该次显示「中断」。
- 并发已满时，提示可点击跳到运行页并能看到占用者。
- 运行中点取消，状态在 3 秒内变为已取消。
- 运行记录超过 30 天被清理。
- `npm test` 全绿，`desktop` 执行 `tsc --noEmit` 与 `vite build` 通过。
