# PRD-1 本机控制台与磁贴执行

## 背景

用户在控制台看到一组磁贴，每块对应一个 target，点击即执行。这是本仓最直接的使用路径：不需要对话，不需要配置。

## 用户故事

**US1 看见能做什么。** 打开控制台看到所有磁贴，每块显示标题、id、并发上限与超时。

**US2 点一下就开始。** 点击执行按钮立即触发，受理期间按钮置灰防重复点击。

**US3 危险操作要确认。** `requiresApproval` 为真的 target，点击后弹确认框，确认才执行。

**US4 看见这次跑到哪。** 执行中持续显示状态与进度；结束显示终态与总用时。

**US5 看见上次跑到哪。** 重新打开页面时显示该 target 最近一次执行的状态与时间。

**US6 看见这次输出了什么。** 点日志图标展开输出面板，可切换历史运行记录。

**US7 能停下。** 运行中的任务可以取消。

## 现状对照

| 用户故事 | 现状 | 缺口 |
| --- | --- | --- |
| US1 | 已实现 | `expose !== "none"` 是恒真判断，`none` 在 schema 里不存在 |
| US2 | 已实现 | `pending` 由 HTTP 返回清空，与任务是否结束无关 |
| US3 | 已实现 | 走 `ConfirmDialog` |
| US4 | 部分 | 只有"运行中/完成/已取消"三种文案，其余落"失败"；无步骤与用时 |
| US5 | 部分 | 每 4 秒轮询 `/api/tiles`，但 `last.state` 直接输出英文枚举 |
| US6 | 已实现 | 运行记录每 1.5 秒刷新，日志每 1 秒刷新 |
| US7 | 未实现 | `tasks/cancel` 服务端可用，界面无入口 |

## 本次增量

### F1 状态文案覆盖全部七态

现状（`desktop/src/pages/actions-page.tsx`）：

```ts
const label =
  state === "working" ? "运行中"
  : state === "completed" ? "完成"
  : state === "canceled" ? "已取消"
  : frame.status?.message || "失败";
```

`submitted` 的 `message` 是空串，所以点击瞬间必渲染"失败"。

要求：建立唯一映射表，覆盖七态。`input-required` 显示"待处理"，`rejected` 显示"已拒绝"并附原因，`failed` 与 `rejected` 不合并。

验收：点击后依次看到"已提交"→"运行中"，不出现"失败"；审批等待期显示"待处理"。

### F2 pending 与任务状态解耦

现状：`setPending(tile.id)` 在请求前，`finally` 里清空。`pending` 只应表示"回执未回"。

要求：回执到达即清空 `pending`，此后状态完全由任务状态驱动。

验收：网络慢时按钮短暂置灰，回执一到即恢复；恢复后状态区继续走"运行中"，不闪回。

### F3 进度可见

现状：`onProgress` 传的是"第 i/n 步"且语义为"已完成 i 步"，界面无步骤信息。

要求：状态区显示"第 i/n 步 · 已用时"。已用时在帧之间本地递增，收到新帧后以服务端 `elapsedMs` 校准。

验收：三步任务能看到 1/3、2/3、3/3 的推进，且 `3/3` 只在最后一步开始时出现。

### F4 重进页面不丢状态

现状：`live` 是组件 state，刷新即丢；但 `App.tsx` 每 4 秒轮询 `/api/tiles`，所以刷新后能恢复到 `last`。问题是 `last.state` 直接输出英文。

要求：`last` 与流帧同构，一套渲染逻辑；对处于非终态的 tile 自动挂 SSE，不必等用户点击。

验收：任务运行中刷新页面，显示"运行中 第 2/3 步"，且继续推进。

### F5 失败要给原因

现状：失败时 `live` 显示"失败"，原因在 `error` state 里且全局共用，多磁贴时串。

要求：失败原因写在对应磁贴的状态区，可展开看详情。并发拒绝显示"并发已满（1/1）"这类具体原因。

验收：连点两次单并发 target，第二次显示"失败 · 并发已满（1/1）"，且不需要等 4 秒轮询。

### F6 可取消

现状：`tasks/cancel` 已实现且会 `emit`，界面无入口。

要求：运行中的磁贴出现取消按钮，调用 `tasks/cancel`，状态转"已取消"。

验收：长任务运行中点取消，子进程被终止（SIGTERM，3 秒后 SIGKILL），状态变"已取消"。

注意一个服务端缺陷：`tasks/cancel` 不判断当前是否已是终态。对一个已完成的任务取消，状态会被改成 `canceled`。F6 上线前应先修这个，否则用户误点会篡改历史状态。

## 边界

- 磁贴状态以 target 为单位展示最近一次执行。同一 target 并发运行多个时只显示最新那次。
- 任务表在内存，sidecar 重启后历史状态丢失，磁贴回到"尚未运行"。见 [ADR-0011](../adr/0011-task-table-in-memory.md)。
- 委派任务（Hub 下发）不写本地任务表，因此不出现在磁贴上。
