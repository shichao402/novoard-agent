# ADR-0002: 单进程载体，agent 自带 HTTP 服务，桌面壳只监管

- 状态：Accepted
- 日期：2026-10-20
- 讨论来源：ADR 重新整理时，发现这条载体决策只在 Hub ADR-0008 里、并被本仓代码注释反复引用，本仓缺一份自述

## Context

目标形态是"三端一致"：Windows、macOS 常驻托盘，Linux 无头；三端能力相同、接口相同。

可选载体有三类：

1. 桌面应用内嵌业务逻辑（Electron/Tauri 里直接跑 node 逻辑）。
2. 独立后端进程 +薷桌面壳，壳只负责窗口与进程监管。
3. 纯 CLI，界面交给浏览器。

第 1 类会让 Linux 无头形态没有界面可依附，三端必然分叉。第 3 类在 Windows/macOS 上用户需要自己记地址、自己开浏览器，且没法做退出与登录启动这类系统集成。

## Decision

agent 是单进程：进程内起本机 HTTP 服务，控制台由它自己托管。桌面壳（Tauri）只做三件事——启动并监管 sidecar、提供 WebView 窗口、做托盘与单实例。业务逻辑一律在 sidecar 里，壳里不写业务。

壳与 sidecar 之间用最小宿主协议：stdout 一行一个 JSON 事件（`ui-ready` / `fatal` / `stopping` / `stopped` / `protocol-error`），stdin 一行一个 JSON 命令；stdin 关闭视为宿主消失，sidecar 主动停机，避免孤儿进程。

端口按版本固定（`edition.json` 的 `localPort`：release 41783、dev 52641），不随机分配。桌面壳据此直接拼地址，不必解析。

## Consequences

- 收益：三端跑同一份服务代码，`local-a2a.mjs` 里没有平台分支；Linux 无头形态就是"不带壳的同一进程"。
- 收益：壳可以被替换（甚至用纯浏览器），业务不受影响。
- 代价：壳必须处理 sidecar 的全生命周期，包括崩溃拉起与停机超时后的强杀兜底。
- 代价：固定端口意味着两个版本不能同时监听同一端口，`edition.json` 因此必须有 dev/release 两档。端口被占用时启动会失败，而非换端口重试。
- 代价：宿主协议是自定义的，没有现成生态，只能自己测。
- 被否决的方案一：业务内嵌进壳。Linux 无头形态无处安放，三端实现必然分叉。
- 被否决的方案二：纯 CLI + 浏览器。缺少托盘、登录启动、单实例这些系统集成，Windows 用户体验不可接受。
- 被否决的方案三：随机端口 + 壳解析 stdout 拿端口。看似更稳，但壳与外部脚本（SSH 转发、书签）都要跟着变；固定端口的可预期性更重要。
