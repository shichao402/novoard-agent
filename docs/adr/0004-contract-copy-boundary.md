# ADR-0004: 契约 SSOT 在 Hub，本仓只持锁定拷贝

- 状态：Accepted
- 日期：2026-10-20
- 讨论来源：ADR 重新整理。此前记录为"契约锁定拷贝"，本次对照 `src/contract/` 与 CI 实现后重写

## Context

本仓 `src/contract/` 下有九张 schema 与 `frames.mjs` 校验器，当前锁定契约 v2.1。CI 会检出 Hub 仓固定 commit 的 SSOT，逐字比较 schema，并对 `frames` 做排除路径锚差异后的语义比较。

这套机制的目的是让本仓可以独立构建、独立发布，同时保证与 Hub 的契约不漂移。

它有两条容易被绕过的路径：

1. 需求驱动：本仓需要某个字段，顺手在本地 schema 里加上，测试也能过，因为自测用的是自己的拷贝。
2. 文档驱动：写文档时把"希望有的字段"写成"已有的字段"，读者据此实现，最后发现 Hub 侧没有。

本次整理的文档里就出现过第二条：文档曾把 `progressUrl` 描述成可选方案，实际它属于契约变更，必须回 Hub 决定。

## Decision

API 契约（A2A 帧、任务对象、target 定义、agent card）的 SSOT 只在 Hub 仓。本仓是消费者：

- `src/contract/` 是锁定拷贝，由同步流程产生，不手工编辑。
- 需要新字段时，先改 Hub 仓的契约文档与 `schemas/`，再同步到本仓，并同时更新拷贝、`CONTRACT_VERSION` 与 CI 固定 commit。
- 本仓文档描述"怎么消费契约"，不重述"字段应该是什么"；需要引字段时链到 Hub 的定义。
- 需求在不改契约的前提下无法满足时，优先用已有字段组合解决；确实做不到，把契约变更作为独立议题提出，不夹带在功能改造里。

本仓自有概念（本机 HTTP 端点、SSE 帧、日志格式、宿主协议）不受此约束，由本仓自行定义。

## Consequences

- 收益：两仓可独立发布，不会出现"本仓认为字段存在、Hub 不认识"。
- 收益：文档不会替契约做决定，减少"按文档写完发现协议不支持"的返工。
- 代价：部分需求要绕路或推迟。对等进度选择了复用既有上行帧而不是新增字段。
- 代价：契约变更需要跨仓协调，节奏不由本仓单方决定。
- 代价：CI 门禁依赖固定 commit，Hub 一旦调整 schema 格式，本仓门禁会先红后修。
- 被否决的方案一：本仓自行扩展 schema，Hub 做兼容。锁定拷贝会名存实亡，两侧对同一字段理解不同时，错误在运行时才暴露。
- 被否决的方案二：取消锁定拷贝，直接依赖 Hub 的 schema 包。本仓无法独立构建，发布受 Hub 版本牵制。
- 被否决的方案三：只锁 schema 不锁 `frames` 校验器。校验器里的错误码与必填判断同样是契约语义，漏锁等于开了后门。
