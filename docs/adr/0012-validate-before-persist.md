# ADR-0012: 定义即校验，不合法不上盘

- 状态：Accepted
- 日期：2026-10-20
- 讨论来源：ADR 重新整理时梳理 `card.mjs` / `targets-store.mjs`，把代码里反复提到的"纪律一"落成决策

## Context

target 定义是 `targets.yaml`，用户可以手写，编辑器也可以保存。定义不合法会导致两类后果：

- 启动期失败：装载即抛错，agent 起不来。
- 运行期失败：跑到一半发现变量没有来源、模板不存在、步骤类型拼错。

第二类更糟：用户在磁贴上点了一下，任务进入 `working`，然后立刻失败，失败原因埋在日志里。

代码里已有的处理：

- `loadTargets` 在装载时用 `createFrameValidator()` 做 schema 校验，失败即返回 `{ ok: false }`，`createLiteAgent` 直接抛错。
- `targets-store.save` 的顺序是：归一文本 → `parse` → `validateTargetsData` → 模板引用预检（`expandSteps`）→ `.bak` 滚动备份 → tmp 原子写（`rename`）→ 从盘重装载 → 返回 `raw/expanded/card`。
- 校验失败时直接返回 `{ ok: false, errors }`，不写盘。

也就是说"不合法定义不上盘"已经实现，只是没写成决策。

## Decision

定义的有效性在写盘前与装载前各校验一次，用的是同一份代码（`validateTargetsData` + `expandSteps`）。校验不通过即拒绝，不落盘、不热替换。

具体规则：

- schema 校验覆盖字段类型、必填项、枚举值、数值范围（`concurrency` 1–32）、时长格式（`^\d+(s|m|h|d)$`）。
- 模板引用必须能被解析，`template` 指向不存在的文件时在写盘前拦下。
- `converse` 是保留 id，target 不得占用。
- 插值占位符必须有来源或有默认值，否则装载即失败（`interp` 抛错，契约 §1.2 明确"不静默替换空串"）。
- 保存前备份为 `targets.yaml.bak`（单份滚动），写入走 tmp + rename，半写文件不可见。

## Consequences

- 收益：错误在写盘前暴露，不会出现"文件已保存但 agent 起不来"。
- 收益：装载与保存共用同一套校验，不会出现"编辑器能存、重启后挂"的漂移。
- 代价：校验较严，写错一个枚举值就会整份拒绝。编辑器必须把 `errors` 逐条展示，否则用户不知道该改哪。
- 代价：`.bak` 只有一份，连续两次错误保存会覆盖掉上一份好的备份。
- 代价：模板预检需要读文件，保存路径变成同步 IO；文件多时保存会略慢，但可接受。
- 被否决的方案一：宽松解析，运行期再报错。用户会先看到一个任务失败，再去翻日志找原因，反馈路径太长。
- 被否决的方案二：自动修正非法值（例如把 `expose: all` 改成 `a2a`）。会让用户以为写对了，埋下更难查的问题。
- 被否决的方案三：保存时只校验 schema，模板在运行时展开。模板缺失是常见错误，应该在保存时拦住。
