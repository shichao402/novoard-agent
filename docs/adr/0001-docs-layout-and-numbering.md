# ADR-0001: 本仓 ADR 独立编号，跨仓引用必须限定来源

- 状态：Accepted
- 日期：2026-10-20
- 讨论来源：ADR 重新整理。此前本仓 ADR 续接 Hub 编号从 0011 起，实际使用后判定应改为独立编号

## Context

本仓从 Hub 拆出，文档布局沿用 Hub 的七段式。ADR 编号一度选择续接 Hub（本仓从 0011 起），理由是"交叉引用不歧义"。

实际核对代码后发现这个理由站不住，因为真正的歧义源在另一侧：

`src/` 里已经存在指向 Hub 的 ADR 引用，而且没有任何前缀：

- `src/local-a2a.mjs` 顶部：`ADR-0008 载体决策落地`
- `src/local-a2a.mjs`：`与 hub 侧同一份语义，ADR-0004`
- `src/main.mjs`：`本地 A2A 端点（ADR-0008；...）`
- `src/tunnel-client.mjs`：`ADR-0008：hub 在线时本地与全局状态同步`
- `src/contract/schemas/target.json`：`调度归 agent 本地（ADR-0003）`

这些编号指的都是 Hub 仓的决策（0003 hub-and-spoke、0004 A2A 通用语、0008 桌面载体）。只要本仓也产出一套 0003/0004/0008，同一串字符就会在两仓指代不同决策，且读者无法从上下文判断。

续接编号只是把碰撞点推迟：本仓 ADR 迟早会写到 0008 以上，届时 `ADR-0008` 依旧二义。

## Decision

本仓 ADR 从 0001 独立编号，不与 Hub 连续。跨仓引用一律显式限定来源：`Hub ADR-0008`、`本仓 ADR-0002`。代码注释引用 Hub 决策时必须带 `Hub` 前缀。

文档布局仍与 Hub 一致（`adr / architecture / prd / research / guides / roadmap / archive`），只有编号独立。

## Consequences

- 收益：编号空间自洽，新增 ADR 不必关心 Hub 用到第几号；跨仓引用靠前缀消歧，不依赖编号区间。
- 收益：本仓 ADR 可以按自己的主题顺序排（载体 → 边界 → 执行 → 状态 → 通道），不必迁就 Hub 的时间线。
- 代价：代码里现有的裸 `ADR-0003` / `ADR-0004` / `ADR-0008` 需要补 `Hub` 前缀，否则与本文档规则冲突。这批注释暂未改动，列在 roadmap 的待办里。
- 代价：本仓与 Hub 的 ADR 编号不再有对应关系，给"两仓同一条决策"（例如 A2A 通用语）做交叉说明时需要各写一次。
- 被否决的方案一：继续续接 Hub 编号。碰撞点只是后移，且本仓文档必须等 Hub 定编号，节奏被牵制。
- 被否决的方案二：两仓合并一套全局编号。需要跨仓协调器与锁，收益不抵成本。
- 被否决的方案三：不编号，用日期或标题。引用会变成一长串标题，代码注释里塞不下。
